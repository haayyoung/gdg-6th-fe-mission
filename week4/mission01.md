1. 리팩토링(Refactoring)의 필요성 

App.js 파일 하나에 API 연결 로직, 데이터가 없을 때의 UI, 데이터가 있을 때의 UI(Todo 목록) 등 모든 코드가 집중되어 있어 분리가 필요한 상황입니다.

여러 개발자가 협업하며 거대한 코드를 효율적으로 관리하기 위해, 코드를 역할과 관심사에 따라 컴포넌트(부품) 단위로 쪼개어 파일별로 따로 개발하는 리팩토링을 진행합니다.

3. 컴포넌트 분리 및 Props 전달 

EmptyData 컴포넌트 분리: App.js에 있던 '데이터가 아직 없음'을 나타내는 UI 코드를 EmptyData.js로 옮기고, App.js에서 이를 임포트하여 삽입합니다. 


Todo 컴포넌트 분리 및 Props 활용: 
App.js 내부 맵(map) 함수 안에서 돌던 반복되는 리스트 UI 코드를 Todo.js로 이동합니다.

하위 컴포넌트인 Todo가 데이터를 인식할 수 있도록 부모(App.js)로부터 Props(프로퍼티스)를 통해 todo.id와 todo.title 등의 데이터를 인자로 내려받도록 코드를 수정합니다. 

이를 통해 App.js 코드가 직관적이고 간소해지며 마치 HTML 같은 구조를 갖추게 됩니다.

4. 리팩토링의 정의 

리팩토링이란?: "결과의 변경 없이 코드의 구조를 재조정하는 작업"입니다. (결과물과 로직은 똑같이 작동하되 코드만 깔끔해지는 것)

처음부터 코드를 완벽하게 짜기는 어렵기 때문에, 먼저 동작하는 코드를 작성한 뒤 가공(리팩토링)을 거치며 좋은 코드로 발전시켜 나가야 합니다.

1. 비동기 처리의 이해
비동기 처리란? 코드가 순차적으로 실행되는 '동기(Synchronous)' 방식과 달리, 특정 작업(예: API 요청)이 끝날 때까지 기다리지 않고 다음 코드를 먼저 실행하는 방식입니다. 

필요성: 서버에서 데이터를 받아오는 데 시간이 걸릴 때, 브라우저가 멈춰 있는 현상을 막아줍니다. 화면의 다른 부분을 먼저 보여준 뒤, 데이터가 오면 해당 부문만 업데이트하여 유저 이탈을 방지합니다. 

2. API URL과 데이터 형식 
JSON 데이터: 자바스크립트 객체와 유사한 형태를 가진 문자열 중심의 데이터 양식입니다. 

fetch 함수: fetch()를 통해 가져온 제이슨(JSON) 문자열 데이터를 자바스크립트가 실제로 사용할 수 있는 '객체'로 변환하는 과정(response.json())을 거쳐 화면에 출력합니다. 

3. 실습을 위한 폴더 및 파일 세팅 
효율적인 파일 관리를 위해 src 폴더 내부에 3개의 폴더를 생성하고 역할을 나눕니다. 

components: 공통 컴포넌트 (Todo, EmptyData 등) 

hooks: 커스텀 훅 파일 

pages: 각 유저별 페이지 (User1Page, User2Page) 

rfce 익스텐션 단축키를 활용하여 기본적인 함수형 컴포넌트 틀을 만듭니다. 

4. 커스텀 훅(Custom Hook) 만들기 
등장 배경: 여러 페이지(User1, User2)에서 useState나 useEffect를 활용해 데이터를 페칭하는 로직이 중복될 때, 이를 하나로 합쳐 재사용하기 위해 사용합니다. 

구현 및 적용: useFetchUser라는 나만의 훅을 만들어 내부 로직을 숨기고, 사용처에서는 유저 ID(숫자)만 인자로 넘겨주면 바로 todos 데이터를 받아올 수 있도록 리팩토링을 진행합니다. 


5. 리액트 라우터(React Router) 소개
URL 경로에 따라 다른 페이지(컴포넌트)를 보여주기 위해 react-router 라이브러리를 사용합니다. 

package.json: 프로젝트에 설치된 라이브러리 정보를 확인할 수 있는 파일로, npm i react-router 명령어를 통해 라이브러리를 추가합니다. 

라우터 설정: index.js에서 기본 경로(/)나 특정 경로(/user/1, /user/2)에 어떤 페이지 컴포넌트를 매핑할지 설정하는 프로바이더 구조를 작성합니다.
